## Tests, CI, dependencies, security posture

- **Tests.** Coverage is broad: parsers with adversarial fixtures, ER, scoring, MCP ACL leak tests across every caller and tool, audit, deliverables, SSO and pull. **However**, the CRM pull and OIDC tests use mocked HTTP and locally made keys. They have never met real HubSpot, Salesforce or an identity provider.
- **Secrets.**
  - `.env.example` only. Tokens are stored hashed.
  - Pull tokens come from environment variables, and errors never echo the token (`pull.py:_get`).
  - The pull follows only pagination links on the same host it started from (`_same_host`).
- **Auth on HTTP.**
  - The token's identity overrides the `caller` argument, so a model can't claim someone else's access.
  - The server binds to 127.0.0.1 by default. TLS is left to the client's reverse proxy.
- **Licensing.** Benchmarks use public datasets downloaded at pinned revisions into a cache outside the repo. Only aggregate numbers are committed, and non-commercial licences were skipped (decisions 66 and 89).
- **Reproducibility.** The `uv.lock` lockfile, a pinned base image and a CI Docker build.
